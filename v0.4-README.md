# FusionLoom v0.4 Release Notes

## Overview

Version 0.4 introduces significant improvements to the LLM chat functionality, enabling seamless integration with Claude, ChatGPT, and Gemini APIs. This update addresses CORS issues that previously prevented direct API calls from the browser by implementing a proxy server approach.

## Key Features

- **API Proxy Server**: Added proxy endpoints in the settings API server to handle requests to external LLM APIs, resolving CORS limitations.
- **Claude Integration**: Full support for Anthropic's Claude API with model selection and chat functionality.
- **ChatGPT Integration**: Complete OpenAI GPT model support with conversation capabilities.
- **Gemini Integration**: Google's Gemini AI models are now fully supported.
- **Improved Error Handling**: Better error messages and recovery options when API calls fail.

## Technical Changes

### Backend Changes

1. **Settings API Server Enhancements**:
   - Added proxy endpoints for Claude, OpenAI, and Gemini APIs
   - Implemented request forwarding with proper authentication
   - Added support for model listing and chat completion endpoints

2. **Dependencies**:
   - Added `requests` library requirement for proxy functionality

### Frontend Changes

1. **LLM Module Updates**:
   - Modified API calls to use proxy endpoints instead of direct API access
   - Improved error handling and reporting
   - Enhanced model selection and initialization

2. **Chat Interface**:
   - Consistent UI across all LLM providers
   - Improved message rendering and formatting
   - Better handling of API keys and settings

## Setup Instructions

1. Ensure you have valid API keys for the LLM services you want to use:
   - Claude: Obtain from [Anthropic Console](https://console.anthropic.com/)
   - ChatGPT: Get from [OpenAI Platform](https://platform.openai.com/)
   - Gemini: Available from [Google AI Studio](https://makersuite.google.com/)

2. Enter your API keys in the Settings page of FusionLoom.

3. Make sure the settings API server is running:
   ```bash
   cd server
   ./run_settings_api.sh
   ```

4. Launch FusionLoom:
   ```bash
   ./launch.sh
   ```

## Known Issues

- File attachments are not yet fully supported for external LLM APIs
- Some advanced model parameters (temperature, top-p, etc.) are not yet configurable through the UI
- Streaming responses are not yet implemented

### v0.4.2 - Hardware-Specific Optimizations

**Implemented Features:**
- **Container Optimization**: Verified and optimized Ollama container files for different hardware platforms:
  - **DGX Systems**: Specialized containers for NVIDIA DGX hardware with multi-GPU support, optimized for 128GB memory systems with 96GB allocation to Ollama
  - **Jetson Devices**: Detailed optimizations for specific Jetson models:
    - **Orin Nano 4GB**: Optimized with 3GB memory allocation and 4 threads
    - **Orin Nano 8GB**: Optimized with 6GB memory allocation and 6 threads
    - **Orin NX 8GB**: Optimized with 6GB memory allocation and 8 threads
    - **Orin NX 16GB**: Optimized with 12GB memory allocation and 8 threads
    - **AGX Orin 32GB**: Optimized with 24GB memory allocation and 12 threads
    - **AGX Orin 64GB**: Optimized with 48GB memory allocation and 16 threads
  - **NVIDIA Consumer GPUs**: Containers optimized for GeForce and other consumer NVIDIA cards
  - **Default Build**: Generic build for systems without specialized hardware
  - **ROCm Build**: Dedicated build for AMD GPUs using the ROCm platform
  - **Apple Silicon**: Optimized for M1/M2/M3/M4 series with Metal GPU acceleration, Metal Performance Shaders, and CoreML optimizations
- **Setup GUI Enhancement**: 
  - Modified setup interface to display different build options with hardware detection
  - Added Jetson model selection submenu with detailed options for each model variant
  - Added support for selecting multiple builds for systems with mixed hardware (e.g., AMD and NVIDIA GPUs)
  - Set power mode default to "Performance" for optimal processing
  - Added hardware detection to automatically suggest optimal container configuration
- **Container Management**:
  - Added container health monitoring for hardware-specific builds
  - Implemented automatic fallback to CPU if GPU containers fail
  - Added resource usage monitoring specific to each hardware platform
